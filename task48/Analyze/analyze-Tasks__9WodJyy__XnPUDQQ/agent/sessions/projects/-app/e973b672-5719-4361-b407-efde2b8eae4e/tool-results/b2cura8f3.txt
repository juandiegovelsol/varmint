MSG: Confirmed the root cause. In fullscreen, the UIManager's `root_container` is positioned at a positive `offset` (the black bars centering the 800×700 play area), so every element's `get_abs_rect().x` includes that offset. But `adjust_row` builds a fixed-size row list sized for the 800-wide logical play area and indexes into it using the raw absolute x — so in fullscreen the index overshoots the list length and `row.pop(index + 1)` throws `IndexError: pop index out of range`.

The fix: subtract the screen offset before computing the index (so it maps into the play-area coordinate space), and clamp defensively so an edge element can never index past the row.

## Summary

**The bug:** Starting the game in fullscreen crashed immediately with `IndexError: pop index out of range` in `scripts/ui/focus_matrix.py:adjust_row` (visible in the second screenshot's traceback; the first screenshot just showed the game's file-explorer window behind the crash).

**Root cause:** `adjust_row` builds a fixed-size row list sized for the **800-wide logical play area**, then indexes into it using an element's `get_abs_rect().x`. In fullscreen, the UIManager positions its `root_container` at a positive `offset` (the black bars centering the 800×700 play area within the monitor), so `get_abs_rect().x` includes that offset. On a 1920-wide display an element's absolute x could be ~1340, giving `index ≈ 134` against an 81-slot row. `list.insert` silently clamps to the end, but the following `row.pop(index + 1)` then popped past the list end and threw. In windowed mode the offset is `(0, 0)`, so it never surfaced.

**The fix** (`scripts/ui/focus_matrix.py`):
1. Subtract `screen_settings.offset[0]` from the absolute x before computing the index, mapping it back into the play-area coordinate space the row size is based on.
2. Clamp the index to `[0, len(row) - 1]` as defense-in-depth so an edge element can never index past the row.
